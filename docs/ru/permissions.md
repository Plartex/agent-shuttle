# Руководство по разрешениям и безопасности

[English version / Английская версия](../permissions.md)

Agent Shuttle реализует стандартизированную многоуровневую модель безопасности и политик инструментов для различных агентных сред (харнессов). В этом руководстве объясняется, как политики проецируются на конкретные среды, как контролируются права доступа и какие границы безопасности необходимо соблюдать.

---

## Четыре стандартные политики инструментов

Agent Shuttle разделяет разрешения инструментов на четыре уровня:

| Политика | Ранг | Описание |
|---|---|---|
| **`no_tools`** | 0 | Полный запрет вызова инструментов. Модель работает исключительно как генератор текста и собеседник. |
| **`read_only`** | 1 | Разрешены только инструменты чтения и поиска (чтение файлов, листинг каталогов, поиск по коду grep) без модификации файлов и выполнения команд shell. |
| **`workspace_write`** | 2 | Разрешено создание и изменение файлов в пределах заданного рабочего каталога проекта. Доступ к внешним каталогам и деструктивные действия заблокированы. |
| **`full_access`** | 3 | Отключает все запросы подтверждения и ограничения инструментов во всем харнессе. |

---

## Проекция политик на харнессы

Каждый базовый харнесс управляет безопасностью по-своему. Agent Shuttle транслирует единые политики в механизмы конкретного харнесса следующим образом:

### 1. Codex

Codex управляется через официальный Python SDK `openai-codex`, использующий встроенные песочницы:

- **`no_tools`**: **Не поддерживается.** Codex App Server требует активной среды песочницы; запрос `no_tools` приводит к ошибке `ValueError("Codex cannot enforce no_tools")`.
- **`read_only`**: Соответствует `Sandbox.read_only`.
- **`workspace_write`**: Соответствует `Sandbox.workspace_write`.
- **`full_access`**: Соответствует `Sandbox.full_access` (отключает изоляцию песочницы и подтверждения действий).

### 2. Antigravity CLI

Antigravity выполняется через официальный CLI `agy` в headless-режиме (`-p` / `stream-json`):

- **Режим разрешений по умолчанию (`settings`)**:
  - CLI учитывает точечные правила, заданные в пользовательском файле `~/.gemini/antigravity-cli/settings.json`.
  - **Ограничение headless-режима:** В неинтерактивном режиме CLI не может запросить подтверждение у пользователя. Поэтому действия, требующие подтверждения (`ask`) или запрещенные (`deny`), отклоняются сразу. Приоритет правил: `deny` > `ask` > `allow`.
  - **Обнаружение мягкого отказа (Soft Denial):** При отказе в вызове инструмента `agy` может завершиться с кодом 0 и вернуть `status: SUCCESS`, но с заполненным полем `denied_actions` или пустым ответом. Agent Shuttle анализирует выходной JSON и выбрасывает `AntigravityPermissionDenied` или `RuntimeError`, предотвращая передачу пользователю вводящего в заблуждение неполного результата.
- **Полный доступ `full_access` (режим `all`)**:
  - Активируется запуском сервера с флагом `--agy-dangerously-skip-permissions` или параметром `HarnessLaunch(tool_policy="full_access")`.
  - Передает флаг `--dangerously-skip-permissions` всем вызовам CLI на этом сервере.
- **`read_only` и `no_tools`**: **Не поддерживаются.** Antigravity CLI в headless-режиме не предоставляет гарантированного механизма песочницы или флага только для чтения. Agent Shuttle явно отклоняет такие запросы до старта модели, предотвращая ложное ощущение безопасности.

### 3. OpenCode

OpenCode запускается как изолированный фоновый HTTP-сервер (`--pure serve`) с авторизацией по токену и генерацией конфигурации через переменную `OPENCODE_CONFIG_CONTENT`:

- **`no_tools`**: Передает `{"permission": {"*": "deny"}}` и системную инструкцию не вызывать инструменты.
- **`read_only`**: Передает `{"permission": {"*": "deny", "read": "allow", "glob": "allow", "grep": "allow", "lsp": "allow"}}`.
- **`workspace_write`**: Передает `{"permission": {"*": "allow", "external_directory": "deny"}}`. Запрещает операции записи за пределами проекта.
- **`full_access`**: Передает `{"permission": {"*": "allow"}}` (разрешает все инструменты и доступ к внешним каталогам).

### 4. Claude Code

Claude Code запускается в print-режиме (`claude -p`) с изолированными временными каталогами конфигурации:

- **`no_tools`**: Запускается с аргументами `--safe-mode --tools "" --permission-prompts none`.
- **`read_only`**: Запускается с аргументами `--safe-mode --tools "Read,Glob,Grep" --permission-prompts none`.
- **`workspace_write`**: Обычный режим работы внутри указанного каталога проекта.
- **`full_access`**: Запускается с флагом `--dangerously-skip-permissions`.

## Серверные профили и защита от повышения привилегий

Для OpenCode и Claude Code политики безопасности фиксируются в серверных JSON-профилях (`AgentProfile`).

Каждый профиль задает предельный уровень `max_tool_policy`:
```json
{
  "id": "code-reviewer",
  "runtime": "opencode",
  "provider": "ollama",
  "default_model": "qwen3.5:9b",
  "allowed_models": ["qwen3.5:9b"],
  "default_tool_policy": "no_tools",
  "max_tool_policy": "read_only"
}
```

- При запросе задачи с флагом `--tool-policy` метод `profile.resolve()` проверяет запрашиваемый уровень относительно `max_tool_policy`.
- Если клиент пытается запросить `workspace_write` или `full_access` для профиля с ограничением `read_only`, Agent Shuttle сразу отклоняет запрос до запуска процесса.
- Клиент не может несанкционированно повысить свои привилегии сверх настроек профиля.

## Критические риски режима `full_access`

> [!CAUTION]
> Политика `full_access` отключает все запросы подтверждения действий и позволяет агенту выполнять любые консольные команды, изменять системные файлы и обращаться к каталогам вне проекта.

1. **Действие на весь сервер:**  
   В Antigravity (`--agy-dangerously-skip-permissions`) и Codex (`Sandbox.full_access`) режим `full_access` действует на **весь запущенный процесс сервера** и все последующие шаги. Он не изолирован отдельным запросом или сессией.
2. **Локальный доступ нескольких клиентов:**  
   Поскольку локальный A2A-сервер слушает интерфейс `127.0.0.1` без пароля, любой локальный процесс на компьютере может подключиться к этому порту и выполнять задачи с максимальным уровнем привилегий.
3. **Не запускайте недоверенные задачи:**  
   Не передавайте непроверенный сторонний код, потенциальные промпт-инъекции или задачи сомнительного происхождения в агент, работающий с `full_access`. Если требуется исследовать недоверенный код, изолируйте Agent Shuttle и агентную среду внутри виртуальной машины или защищенного контейнера.

## Безопасная настройка параметров Antigravity

Если вам требуется частичный доступ к инструментам Antigravity без снятия всех ограничений (`full_access`), настройте точечные правила в файле `~/.gemini/antigravity-cli/settings.json`:

```json
{
  "permissions": {
    "allow": [
      "read_file",
      "list_dir",
      "grep_search"
    ],
    "deny": [
      "system_restart",
      "format_disk"
    ]
  }
}
```

- Не используйте значение `"ask"` для автоматических и headless-сценариев, так как при отсутствии интерактивного терминала оно интерпретируется как запрет (`deny`).
- Agent Shuttle не изменяет `settings.json` автоматически.

---

## Сетевая изоляция

Серверы Agent Shuttle привязываются исключительно к `127.0.0.1` (loopback). Протокол HTTP A2A не использует шифрование TLS и не требует авторизации. Публикация этих портов во внешнюю или локальную сеть без реверс-прокси с TLS и аутентификацией создает прямую угрозу удаленного выполнения произвольного кода.
